# Get Shit Done (GSD) Execution Rules

When operating under the GSD protocol, adhere strictly to these rules:

1. **No Incomplete Stubs**: Never leave placeholder functions, empty try/except blocks, or mock functions unless explicitly requested as a fixture.
2. **Execute First, Explain Later**: Prioritize writing, updating, and running code before delivering long explanatory prose.
3. **Decisive Engineering**: If an architectural choice has standard industry consensus (e.g., REST vs gRPC for simple web, SQLite vs Postgres for local prototypes), choose the simplest industry default and proceed.
4. **Immediate Verification**: Always run a test command or validation script after editing code to confirm zero regressions.
5. **No Wall of Text**: Keep responses crisp, actionable, and formatted with clear headings, bullet points, and code diffs.
